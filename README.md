# myday-hub

A personal calendar aggregator that will show Google Calendar and Outlook events in one place.
**Status:** scaffold only. There's no calendar syncing yet.

- **Backend:** Python 3.12, FastAPI, SQLAlchemy 2.x, Alembic, Postgres (`backend/`)
- **Frontend:** React + TypeScript + Vite (`frontend/`)
- **Production:** one Docker image. FastAPI serves the API at `/api` and the built React app at `/`

## Run locally (Docker Compose)

```bash
cp .env.example .env        # then edit values if you like
docker compose up --build
```

| URL | What |
|---|---|
| http://localhost:5173 | Frontend (Vite dev server, hot reload) |
| http://localhost:8000/api/health | Health check (also checks the DB) |
| http://localhost:8000/api/events | Events list (empty for now) |
| http://localhost:8000/docs | Interactive API docs (generated by FastAPI) |

Edits under `backend/` restart the API automatically, and edits under `frontend/src/` update the browser instantly.
Database migrations run automatically every time the API container starts.

Stop with `Ctrl+C`. To also delete the database data: `docker compose down -v`.

## Tests

```bash
docker compose run --rm api pytest
```

The current tests don't need a database. To run them without Docker:

```bash
cd backend
python3 -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
pytest
```

## Database migrations (Alembic)

When you change `backend/app/models.py`:

```bash
docker compose run --rm api alembic revision --autogenerate -m "describe the change"
# Read the new file in backend/alembic/versions/ and fix anything that's wrong, then:
docker compose run --rm api alembic upgrade head   # (or just restart the api container)
```

## Production image

```bash
docker build -t myday-hub .
docker run --rm -p 8000:8000 -e DATABASE_URL=postgresql+psycopg://USER:PASS@HOST:5432/DB myday-hub
```

Open http://localhost:8000. To try it against the dev database, use `--network myday-hub_default` and set `HOST` to `db`.

## Configuration

All configuration comes from environment variables. See `.env.example` for the full list.
`.env` holds your real values and is git-ignored, so never commit it.
